# Project detail rendering allows a per-project override component

ADR 0001 made the generic, JSON-driven `ProjectDetail` renderer — one typed `ProjectItem` interface with optional sections — the default for every project's detail page. This ADR adds a narrow, explicit exception: a project id can be mapped in `ProjectDetail.tsx`'s override registry to a dedicated, fully hardcoded component when that project's story doesn't fit the optional-section shape well enough to justify forcing it in, bypassing `ProjectItem`'s content fields for that project's detail body entirely. The Projects list page is unaffected by this: it always sources its summary fields (title, subtitle, company, dates, tags) from JSON regardless of whether a given project's detail page is generic or overridden. The cost: an overridden project's detail content lives only in code, not JSON, so it can't be edited without a code change, and each override component duplicates structural layout (stat cards, tabs) that the generic renderer would otherwise share — accepted as the price of a bespoke narrative for projects that need one.
